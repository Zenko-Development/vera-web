# API мобильного приложения скорой

[Общие правила API](API_DOCUMENTATION.md) · [API веб-клиента](API_WEB_CLIENT.md)

Все пути ниже указаны относительно `/api/v1`. Приложение работает от имени
планшета: ФИО и учётная запись сотрудника для начала смены не требуются.
Обмен с backend — HTTP с JSON; WebSocket-маршрутов нет.

## Подготовка и смена

Администратор заранее создаёт машину и показывает QR, полученный из
`data.qr_payload` ответа `POST /device/` (или сброса секрета). Сканер читает
JSON-строку, проверяет `type == "vera.device.provisioning"` и `version == 1`,
затем сохраняет `device_id` и `auth_secret` в защищённом хранилище устройства
(Android Keystore / iOS Keychain). QR содержит действующий секрет, поэтому
не сохраняйте изображение, не логируйте его и не отправляйте в аналитику.
`auth_secret_hash` планшет никогда не получает. Бригада вводит номер машины
отдельно; приложение отправляет:

```http
POST /api/v1/device-access/login
Content-Type: application/json
```

```json
{
  "device_id": "DEVICE_ID_FROM_PROVISIONING",
  "auth_secret": "SECRET_FROM_SECURE_STORAGE",
  "car_number": "A123BC77"
}
```

Ответ содержит `data.access_token`, `data.refresh_token`, `data.expires_at`.
Последнее поле обозначает окончание смены. На защищённые маршруты передавайте
`Authorization: Bearer <DEVICE_ACCESS_TOKEN>`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/device-access/login` | Открыть смену на существующей машине |
| POST | `/device-access/refresh` | Заменить пару токенов, сохранив новый refresh-токен |
| POST | `/device-access/logout` | Завершить смену |

Refresh/logout принимают `{"refresh_token":"…"}`. Login/refresh/logout
расположены вне middleware идемпотентности: `Idempotency-Key` их не защищает.
Полные ответы и ошибки: [доступ устройства](api/device-ambulance-access.md#вход-устройства-и-управление-сменой).

## Последовательность работы

1. Открыть смену и начать отправку позиции планшета с частотой из GPS-политики.
   После перезапуска запросить активный вызов и активный run.
2. Создать вызов, если активного нет, и загрузить GPS-политику.
3. Запустить передачу координат для активного вызова.
4. Получить `/device/checklists`, выбрать `checklist_id`, создать run с ним и `emergency_call_id`, загрузить `/form`.
5. Сохранять ответы, затем вызвать `/checklist-runs/{id}/complete`.
6. Выполнить `/destination/resolve`: `fixed` и `by_service_area` могут сразу
   вернуть выбранную больницу; для `by_tag` выбрать кандидата через `/select`.
7. Во время поездки продолжать отправлять GPS и читать `/arrival-estimate`.
8. По окончании вызова выполнить `/complete` либо `/cancel` и остановить GPS
   для этого вызова. Выбор больницы сам по себе не означает завершение поездки.
9. По окончании смены выполнить logout.

Если `no_candidates`, приложение показывает отсутствие подходящего направления.
При `404` на ETA прогноз пока отсутствует; не заменяйте его нулём минут.

## GPS и обновление ETA

Последнюю позицию планшета на смене, даже когда активного вызова нет, приложение
передаёт в `POST /device-access/location`:

```json
{
  "latitude": 55.755826,
  "longitude": 37.6173,
  "accuracy_meters": 8.5,
  "captured_at": "2026-09-22T12:04:55Z"
}
```

Для этого потока частота определяется `device_location_interval_seconds`
(по умолчанию 30 секунд). Для координат активного вызова используйте отдельный
`POST /emergency-calls/{id}/locations`, который продолжает хранить историю и
пересчитывать ETA; его частота задаётся `active_call_interval_seconds`
(по умолчанию 15 секунд). Для обоих потоков действует `max_accuracy_meters`.
Разрешения ОС и фоновое выполнение реализует мобильный клиент; backend
принимает точки и проверяет ограничения. `429` означает слишком частую
отправку, `400` может означать превышение допустимой погрешности, `409` — что
клиент прислал координату старее уже принятой.

После новой точки сервер обновляет ETA, если больница уже выбрана и имеет
координаты. Клиент получает прогноз отдельным GET-запросом, например после
успешной отправки точки. Сотрудник больницы получает тот же тип прогноза через
свой веб-маршрут `/hospital-arrivals`. Push-уведомлений об обновлении нет.

Показывайте время `estimated_arrival_at` вместе с `location_is_fresh`.
`estimated_travel_seconds` — длительность при последнем расчёте, а не
автоматически уменьшающийся счётчик. Расчёт приблизительный: расстояние по
координатам, дорожный коэффициент и настроенная средняя скорость.

## Повтор запросов при плохой связи

Для изменяющих защищённых маршрутов из таблицы передавайте
`Idempotency-Key: <UUID>`. Сохраняйте ключ и исходные байты тела до получения
ответа; при сетевом повторе используйте их снова. Для нового действия нужен
новый ключ. Ключ ограничен сессией, методом и путём; сохранённый ответ
повторяется в течение 24 часов с `Idempotency-Replayed: true`.

`409` может означать другое тело с тем же ключом или ещё выполняющийся запрос.
Сейчас сохраняются и ответы `4xx`, включая `429`; повтор такого запроса с тем
же ключом вернёт сохранённую ошибку. `5xx` не сохраняются.

Текущая реализация сохраняет HTTP-ответ отдельно от бизнес-транзакции.
При сбое между выполнением операции и сохранением ответа повторное выполнение
возможно; полноценная атомарная гарантия ещё требует доработки backend.

## Текущая граница API

Списки `/checklist/`, `/sickness/`, `/hospital/`, `/ambulance-vehicles/`
защищены employee JWT. Для выбора формы планшет использует
`GET /api/v1/device/checklists` с device access token. Ответ `200 OK` содержит
`data` — массив объектов `{id, name, description, sickness_id,
published_version_id, version}`. Выбирайте `id` как `checklist_id` при старте
run. Черновики и архивные версии не включаются. Если опубликованных версий
нет, возвращается `{"data":[]}`; отозванная или истёкшая смена получает `401`.
Форму выбранной версии загружайте через `/checklist-runs/{id}/form`.

Пример ответа каталога:

```json
{
  "data": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "name": "Инсульт",
      "description": "Оценка симптомов",
      "sickness_id": "22222222-2222-4222-8222-222222222222",
      "published_version_id": "33333333-3333-4333-8333-333333333333",
      "version": 3
    }
  ]
}
```
