# Прохождение чеклиста устройством

[К общей документации API](../API_DOCUMENTATION.md)

Эти ручки принадлежат приложению бригады скорой. В отличие от административных API чеклистов, каждая из них требует access-токен устройства:

```http
Authorization: Bearer <DEVICE_ACCESS_TOKEN>
```

Токен получается через `POST /api/v1/device-access/login`. Сервер дополнительно проверяет, что сессия устройства всё ещё активна, принадлежит указанному устройству и не истекла. Поэтому access-токен нельзя использовать после logout или истечения смены.

Успешные ответы используют оболочку `data`, ошибки — `message`.

## Статусы

- `in_progress` — прохождение создано и ожидает ответы.
- `cancelled` — бригада отменила прохождение; `completed_at` заполнен.
- `completed` — обязательные вопросы заполнены, Rule Engine сохранил итоговый результат; прохождение больше не редактируется.

У одной `device_access_session` может быть только один `in_progress` run. После отмены или завершения та же бригада сможет начать новый.

## Объект run

```json
{
  "data": {
    "id": "2ae534f1-0a14-4780-9a4b-8204fe3985ca",
    "checklist_version_id": "64e27ef9-c8f7-4b27-b4fe-30d312f8c935",
    "device_access_session_id": "f7c8a0ad-38d7-466c-a161-adcab452ef2e",
    "emergency_call_id": "1022cf0d-2334-4a18-af99-126e8a4141ca",
    "status": "in_progress",
    "started_at": "2026-09-18T12:00:00Z",
    "completed_at": null,
    "created_at": "2026-09-18T12:00:00Z",
    "updated_at": "2026-09-18T12:00:00Z"
  }
}
```

`checklist_version_id` — точная опубликованная версия, выбранная сервером на момент старта. Даже если позднее выйдет новая версия, ответы данного run будут относиться к этой версии.

## POST /api/v1/checklist-runs/

Начинает прохождение для текущего устройства и активного вызова. До этого
клиент должен открыть вызов через `POST /api/v1/emergency-calls/`. Клиент
передаёт ID чеклиста, но не версию: сервер сам находит его опубликованную
версию.

```json
{
  "checklist_id": "e0343c3d-c77d-43d5-84dc-86fb749598d9",
  "emergency_call_id": "1022cf0d-2334-4a18-af99-126e8a4141ca"
}
```

Ответ: `201 Created`, объект run в `data`.

Ошибки:

- `400` — неверный JSON, неизвестное поле, `checklist_id` или `emergency_call_id` не UUID v4;
- `401` — access-токен отсутствует/неверный, сессия отозвана либо истекла;
- `409` — вызов не активен, не принадлежит этой device-сессии, у чеклиста нет опубликованной версии либо у сессии уже есть активный run;
- `500` — непредвиденная ошибка сервера.

## GET /api/v1/checklist-runs/active

Возвращает незавершённый run текущей сессии. Используется при перезапуске приложения, чтобы продолжить начатое прохождение.

Ответ: `200 OK`, объект run в `data`.

Ошибки: `401` — неактивная/неверная сессия; `404` — активного run нет.

## GET /api/v1/checklist-runs/{id}

Возвращает run по UUID, только если он принадлежит текущей сессии устройства. Run другой бригады не раскрывается и выглядит как отсутствующий.

Ответ: `200 OK`, объект run в `data`.

Ошибки: `400` — неверный UUID; `401` — неактивная/неверная сессия; `404` — run не найден либо принадлежит другой сессии.

## POST /api/v1/checklist-runs/{id}/cancel

Отменяет собственный незавершённый run. Тело не требуется.

Ответ: `200 OK`, объект run со статусом `cancelled` и заполненным `completed_at`.

Ошибки: `400` — неверный UUID; `401` — неактивная/неверная сессия; `404` — run не найден либо чужой; `409` — run уже `completed` или `cancelled`.

## POST /api/v1/checklist-runs/{id}/complete

Завершает собственный run в статусе `in_progress`. Тело не требуется.

Сервер в одной транзакции проверяет активность device-сессии, принадлежность run этой сессии и наличие ответа на каждый вопрос с `required: true` в зафиксированной версии чеклиста. Затем Rule Engine проверяет правила по `priority DESC`, находит первое правило, у которого совпали все условия, сохраняет его результат и только после этого переводит run в `completed`.

Ответ: `200 OK`.

```json
{
  "data": {
    "run": {
      "id": "2ae534f1-0a14-4780-9a4b-8204fe3985ca",
      "checklist_version_id": "64e27ef9-c8f7-4b27-b4fe-30d312f8c935",
      "device_access_session_id": "f7c8a0ad-38d7-466c-a161-adcab452ef2e",
      "emergency_call_id": "1022cf0d-2334-4a18-af99-126e8a4141ca",
      "status": "completed",
      "started_at": "2026-09-18T12:00:00Z",
      "completed_at": "2026-09-18T12:05:00Z",
      "created_at": "2026-09-18T12:00:00Z",
      "updated_at": "2026-09-18T12:05:00Z"
    },
    "result": {
      "id": "a25e6794-ef32-47c1-bf7e-03b4640d1d2a",
      "checklist_run_id": "2ae534f1-0a14-4780-9a4b-8204fe3985ca",
      "checklist_rule_id": "c2dc1794-686d-4743-b4e2-a3ced684f2b2",
      "checklist_result_id": "81fd2fa7-a0fc-4fed-bb4f-b77a0cd8a722",
      "title": "Требуется госпитализация",
      "message": "Направьте пациента в профильное учреждение.",
      "calculated_at": "2026-09-18T12:05:00Z"
    }
  }
}
```

Ошибки: `400` — неверный UUID; `401` — неактивная/неверная сессия; `404` — run не найден либо чужой; `409` — есть обязательный вопрос без ответа, отсутствует подходящее правило либо run уже `completed` или `cancelled`.

## GET /api/v1/checklist-runs/{id}/result

Возвращает ранее сохранённый результат собственного run. Используется после перезапуска приложения: результат не вычисляется повторно и не зависит от последующих версий чеклиста.

Ответ: `200 OK`, объект `result` из ответа `complete` в `data`.

Ошибки: `400` — неверный UUID; `401` — неактивная/неверная сессия; `404` — run чужой/не найден либо у него ещё нет результата.

## GET /api/v1/checklist-runs/{id}/form

Возвращает форму именно той версии чеклиста, которая сохранена в run. Клиенту не нужно отдельно получать вопросы и варианты: этот маршрут подходит для первого отображения формы и для восстановления после перезапуска приложения.

Ответ: `200 OK`.

```json
{
  "data": {
    "checklist_run_id": "2ae534f1-0a14-4780-9a4b-8204fe3985ca",
    "checklist_version_id": "64e27ef9-c8f7-4b27-b4fe-30d312f8c935",
    "questions": [
      {
        "id": "a903d1bb-9be8-4c50-9d8c-31f1b2e5b250",
        "question": "Есть ли сознание?",
        "type": "boolean",
        "position": 1,
        "required": true,
        "options": []
      }
    ]
  }
}
```

Ошибки: `400` — неверный UUID; `401` — токен или сессия устройства недействительны; `404` — run отсутствует или принадлежит другой сессии.

## PUT /api/v1/checklist-runs/{run_id}/answers/{question_id}

Создаёт либо полностью заменяет ответ на один вопрос. Работает только для собственного run в статусе `in_progress`. Повторный `PUT` безопасен: прежнее значение и выбранные варианты заменяются новыми в одной транзакции.

Тело зависит от `type` вопроса:

| Тип | Допустимое тело |
| --- | --- |
| `single` | `{ "option_ids": ["<один UUID варианта>"] }` |
| `multiple` | `{ "option_ids": ["<UUID варианта>", "<UUID варианта>"] }` |
| `text` | `{ "value": "свободный текст" }` |
| `boolean` | `{ "value": "true" }` или `{ "value": "false" }` |
| `number` | `{ "value": "42.5" }` |

Варианты должны принадлежать указанному вопросу. Пустой текст, одинаковый вариант дважды, несоответствие типа и незнакомые поля приводят к `400 Bad Request`.

Ответ: `200 OK`.

```json
{
  "data": {
    "id": "eaac70e7-b24a-4ae8-bba8-5e0cf4ad5694",
    "checklist_run_id": "2ae534f1-0a14-4780-9a4b-8204fe3985ca",
    "checklist_question_id": "a903d1bb-9be8-4c50-9d8c-31f1b2e5b250",
    "value": "true",
    "option_ids": [],
    "created_at": "2026-09-18T12:03:00Z",
    "updated_at": "2026-09-18T12:03:00Z"
  }
}
```

Ошибки: `400` — неверный UUID, тело или тип ответа; `401` — недействительная сессия; `404` — run, вопрос или вариант не найден/не принадлежит контексту; `409` — run уже `completed` или `cancelled`.

## GET /api/v1/checklist-runs/{run_id}/answers/

Возвращает сохранённые ответы собственного run. Поле `option_ids` всегда массив: для `text`, `number` и `boolean` он пустой.

Ответ: `200 OK`, `data` — массив объектов того же формата, что возвращает `PUT`.

## DELETE /api/v1/checklist-runs/{run_id}/answers/{question_id}

Удаляет ответ на вопрос из собственного незавершённого run. Выбранные варианты удаляются вместе с ответом.

Ответ: `204 No Content`.

Ошибки: `400` — неверный UUID; `401` — недействительная сессия; `404` — run не найден/чужой либо ответа на этот вопрос нет; `409` — run уже завершён или отменён.

## Правила вычисления

Условия одного правила работают через `AND`; для логики «или» создаются отдельные правила, ведущие к одному результату. Чем выше `priority`, тем раньше правило проверяется. Опубликованная версия обязана содержать ровно одно правило без условий — fallback — с priority ниже любого правила с условиями. Оно срабатывает последним. Если подходящего правила нет, run не завершается.
