# Зоны обслуживания и маршрутизация больниц

[К общей документации API](../API_DOCUMENTATION.md)

В MVP существующий `facility_type` используется как один тег больницы. Поэтому
режим `by_tag` возвращает все больницы с указанным `facility_type_id`. Позже,
если одной больнице понадобятся несколько независимых тегов, это можно заменить
отдельными таблицами `hospital_tag` и `hospital_tag_assignment` без изменения
сценария назначения.

## Настройка result routing

В `POST` и `PATCH /api/v1/checklist-result-routing/...` поле `routing_type`
теперь принимает одно из значений:

| Тип | Обязательные поля | Поведение |
| --- | --- | --- |
| `fixed` | `hospital_id` | Конкретная больница выбирается сервером сразу. |
| `by_tag` | `facility_type_id` | Возвращается список больниц с этим тегом; бригада выбирает одну. |
| `by_service_area` | нет | Сервер ищет активную зону, содержащую свежую GPS-точку вызова. |

Неиспользуемые идентификаторы в каждом режиме должны отсутствовать, а не
передаваться пустым UUID.

## Объект service area

Зона задаётся замкнутым полигоном в WGS 84. Каждая вершина записывается как
`[latitude, longitude]`; последняя точка должна повторять первую. Полигоны с
самопересечением, незамкнутым контуром или координатами вне диапазона сервер
отклоняет. При пересечении нескольких зон победит зона с большим `priority`.

```json
{
  "hospital_id": "fe0fdcff-1440-4c5e-9e65-69726498e6e9",
  "name": "Центральный район",
  "boundary": [[55.70, 37.50], [55.70, 37.70], [55.85, 37.70], [55.85, 37.50], [55.70, 37.50]],
  "priority": 10,
  "active": true
}
```

Маршруты конфигурации зоны: `POST /api/v1/hospital-service-areas/`,
`GET /api/v1/hospital-service-areas/`, `GET`, `PUT`, `DELETE`
`/api/v1/hospital-service-areas/{id}`. Сейчас, как и другие административные
API MVP, они не защищены глобальным user middleware; перед production это
нужно ограничить ролью администратора.

## Практический поток бригады

1. Записать свежую позицию: `POST /emergency-calls/{id}/locations`.
2. Завершить checklist run.
3. Вызвать `POST /emergency-calls/{id}/destination/resolve`.
4. Для `by_tag` получить кандидатов и выбрать больницу через
   `POST /emergency-calls/{id}/destination/select`.

При `by_service_area` последняя GPS-точка должна быть не старше двух минут.
Выбор всегда сохраняется вместе со snapshot кандидатов — последующая смена
названия, адреса или facility type больницы не меняет историю вызова.
