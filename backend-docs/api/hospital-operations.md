# Расписание операций больницы

План ведётся отдельно для каждой физической операционной. Тип записи —
`planned` или `unplanned`. Приоритет — целое число от `1` (самый высокий) до
`5` (самый низкий). Начало и конец передаются в RFC3339 с точностью до минуты;
`duration_minutes` вычисляется сервером из этих значений.

Фактический статус комнаты (`ready`, `occupied`, `maintenance`) остаётся отдельным
полем. При переходе операции в `in_progress` комната автоматически становится
`occupied`. После `completed` или отмены уже начатой операции она возвращается в
`ready`, если за это время сотрудник не поставил её на `maintenance`.

Все ручки требуют employee access token. Для сотрудника больницы нужны право
`hospital_resource.change_status` и назначение в эту больницу. Роль с
`hospital_resource.manage` может управлять всеми больницами.

## Просмотр плана

`GET /api/v1/hospital-operating-rooms/{room_id}/operations`

Можно передать `from` и `to` как RFC3339, чтобы получить записи, пересекающие
указанный интервал. Нужно передавать оба параметра вместе. Если их нет, сервер
возвращает записи от 30 дней назад до 90 дней вперёд.

## Добавление записи

`POST /api/v1/hospital-operating-rooms/{room_id}/operations`

```json
{
  "title": "Операция на коленном суставе",
  "description": "Подготовка операционной № 2",
  "operation_type": "planned",
  "priority": 2,
  "starts_at": "2026-10-10T09:00:00Z",
  "ends_at": "2026-10-10T11:30:00Z"
}
```

Успешный ответ — `201 Created`. Нельзя создать активную запись, если её интервал
пересекается с другой записью этой комнаты в статусе `scheduled` или
`in_progress`; сервер вернёт `409 Conflict`. Границы интервалов полуоткрытые:
операция, закончившаяся ровно в момент начала следующей, не считается конфликтом.

## Изменение и ход выполнения

- `PUT /api/v1/hospital-operating-operations/{operation_id}` полностью заменяет
  данные записи со статусом `scheduled`.
- `PATCH /api/v1/hospital-operating-operations/{operation_id}/status` принимает
  `{"status":"in_progress"}`, `{"status":"completed"}` или
  `{"status":"cancelled"}`.

Разрешены переходы `scheduled -> in_progress`, `scheduled -> cancelled`,
`in_progress -> completed` и `in_progress -> cancelled`. Начать операцию можно,
только если комната сейчас `ready`; иначе ответ `409 Conflict`. Удаление не
физическое — для сохранения истории запись отменяют. Создание, изменение,
изменение статуса операции и связанное изменение статуса комнаты пишутся в audit
log транзакционно.

## Основные ошибки

- `400` — неверное тело, UUID, тип операции, приоритет или время;
- `403` — нет нужного права или сотрудник не назначен в больницу;
- `404` — операционная или запись плана не найдена;
- `409` — конфликт расписания, недопустимый переход статуса либо операционная
  не готова к началу;
- `500` — внутренняя ошибка сервера.
