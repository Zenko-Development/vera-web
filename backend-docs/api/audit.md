# Аудит событий

[К общей документации API](../API_DOCUMENTATION.md)

Журнал аудита — append-only: записи создаются сервером вместе с бизнес-операцией
и не могут быть изменены или удалены через API. Сейчас в нём фиксируются:

- изменение статуса больничного оборудования и операционных;
- публикация версии чеклиста;
- изменение `acces_status` учётной записи сотрудника;
- изменение роли учётной записи сотрудника;
- построение назначения больницы для вызова;
- выбор больницы бригадой из сохранённого списка кандидатов.
- изменение политики отправки GPS и расчёта ETA.

Маршрут предназначен для сотрудника с правом `analytics.read` (например, роль
`analyst`) и требует employee JWT:

```http
Authorization: Bearer <ACCESS_TOKEN>
```

## GET /api/v1/audit/events

Возвращает события от новых к старым. Параметры строки запроса необязательны:

- `limit` — число записей, от `1` до `100`, по умолчанию `50`;
- `offset` — число пропускаемых записей, от `0`, по умолчанию `0`.

Пример: `GET /api/v1/audit/events?limit=25&offset=0`.

Ответ: `200 OK`.

```json
{
  "data": [
    {
      "id": "54a9af1d-df63-4248-87d6-055d4955d925",
      "event_type": "emergency_call_destination.selected",
      "actor_kind": "device",
      "actor_user_id": null,
      "actor_device_id": "06c7a56a-5eff-4b8b-990f-697089f13242",
      "entity_type": "emergency_call_destination",
      "entity_id": "d7fd7d25-5124-4285-93e2-48d11c96b28f",
      "emergency_call_id": "50afd127-8e1d-4ef3-ab2d-ab1d963a9668",
      "payload": {
        "selected_hospital_id": "999f28c6-5d63-47b4-80fb-a3db7c30b2f4"
      },
      "occurred_at": "2026-09-21T12:00:00Z"
    }
  ]
}
```

Ошибки: `400` — параметры пагинации не являются целыми числами, отрицательны
или `limit` больше `100`; `401` — employee JWT отсутствует либо недействителен;
`403` — у роли нет `analytics.read`.

`payload` зависит от типа события. Для изменения статуса ресурса он содержит
`hospital_id`, `previous_status` и `new_status`; для расчёта назначения —
`routing_type`, `status`, число кандидатов и при автоматическом выборе
`selected_hospital_id`. Для публикации чеклиста — `checklist_id` и номер
опубликованной версии `version`.
Для изменений учётной записи payload содержит только технические идентификаторы
и значения перехода: для доступа — `previous_access_status` и
`new_access_status`, для роли — `previous_role_id` и `new_role_id`.
Пароли, JWT и персональные данные в payload не записываются.
