# Больницы, заболевания и типы учреждений

[К общей документации API](../API_DOCUMENTATION.md)

Маршруты взяты из текущего `cmd/api/main.go`, поля — из DTO и миграций. Статусы, преобразования значений и ограничения поведения сверены с обработчиками, сервисами и выполняемыми SQL-запросами. Это описание текущего кода; особенности ниже не исправлены.

Для запросов с телом используйте `Content-Type: application/json`. UUID передаются строками. Даты в ответах — строки RFC 3339. Параметры поиска по имени и коду передаются в URL с URL-кодированием. У списков нет пагинации, фильтров или гарантированной сортировки. При отсутствии записей все списки этого раздела возвращают `{"data":[]}`.

Обычный JSON-ответ обёрнут в `data`, ошибка — в `message`:

```json
{
  "message": "internal server error"
}
```

Тексты других ошибок указаны у маршрутов. Там, где обработчик оставляет тело пустым или записывает два JSON-объекта подряд, это отмечено отдельно.

## Больницы

Источники: [DTO](../../internal/hospitals/dto.go), [обработчики](../../internal/hospitals/handler.go), [сервис](../../internal/hospitals/service.go), [репозиторий](../../internal/hospitals/repository_sqlc.go), [SQL, выполняемый приложением](../../db/sqlc/hospitals.sql.go), [миграция hospitals](../../db/migrations/007_hospital.up.sql).

| Поле request | Тип JSON | Ограничения и фактическое поведение |
| --- | --- | --- |
| `name` | string | В БД `NOT NULL`, `UNIQUE`; непустая строка в коде не проверяется. |
| `description` | string | В БД допускается `NULL`; отсутствие поля или JSON `null` записывается как `""`. |
| `address` | string | В БД `NOT NULL`; непустая строка в коде не проверяется. |
| `phone` | string | В БД допускается `NULL`; отсутствие поля или JSON `null` записывается как `""`. Формат не проверяется. |
| `facility_type_id` | string, UUID | Для создания нужен существующий тип учреждения; в БД `NOT NULL` и внешний ключ. Непереданное или невалидное значение приводит к ошибке разбора UUID. |
| `latitude` | number | В БД допускается `NULL`; при создании отсутствие или `null` превращается в `0`. Диапазон не проверяется. |
| `longitude` | number | В БД допускается `NULL`; при создании отсутствие или `null` превращается в `0`. Диапазон не проверяется. |

В DTO создания и обновления нет тегов `validate`, поэтому вызов валидатора не делает эти поля обязательными. В ответе все перечисленные поля присутствуют. При чтении SQL `NULL` в `description`/`phone` превращается в `""`, в координатах — в `0`, а в `updated_at` — в `"0001-01-01T00:00:00Z"`.

Пример ответа с одной больницей (`ResponseHospitalDTO`):

```json
{
  "data": {
    "id": "11111111-1111-4111-8111-111111111111",
    "name": "Городская больница №1",
    "description": "Многопрофильная больница",
    "address": "Москва, ул. Примерная, 1",
    "phone": "+7 495 000-00-00",
    "facility_type_id": "33333333-3333-4333-8333-333333333333",
    "latitude": 55.7558,
    "longitude": 37.6173,
    "created_at": "2026-09-09T10:00:00Z",
    "updated_at": "2026-09-09T10:00:00Z"
  }
}
```

### POST /api/v1/hospital/

Создать больницу.

**URL:** `POST /api/v1/hospital/`

**Request:** JSON с полями из таблицы выше. Тип учреждения должен существовать.

```json
{
  "name": "Городская больница №1",
  "description": "Многопрофильная больница",
  "address": "Москва, ул. Примерная, 1",
  "phone": "+7 495 000-00-00",
  "facility_type_id": "33333333-3333-4333-8333-333333333333",
  "latitude": 55.7558,
  "longitude": 37.6173
}
```

**Response:** `201 Created`, объект созданной больницы в `data`; [полный пример JSON](#hospital-response).

Ошибки: `400` — `"invalid json"`; `409` — дубликат `name`, при этом текущая ошибка имеет пустой текст: `{"message":""}`. Невалидный/непереданный `facility_type_id`, отсутствующий тип учреждения и прочие ошибки БД возвращают `500` с `"internal server error"`.

### GET /api/v1/hospital/

Получить все больницы.

**URL:** `GET /api/v1/hospital/`

**Request:** тело отсутствует; параметры не предусмотрены.

**Response:** `200 OK`, `data` — массив объектов [больницы](#hospital-response). Пример пустого списка:

```json
{
  "data": []

```

Ошибка получения списка возвращает `404` с текстом ошибки в `message`.

### GET /api/v1/hospital/{id}

Получить больницу по UUID.

**URL:** `GET /api/v1/hospital/11111111-1111-4111-8111-111111111111`

**Request:** path-параметр `id` — UUID больницы. Тело отсутствует.

**Response:** `200 OK`, объект больницы в `data`; [полный пример JSON](#hospital-response).

Невалидный UUID возвращает `400` с `"invalid id"`. Если записи нет, текущий репозиторий возвращает исходную ошибку, и обработчик отвечает `400` с `"no rows in result set"`; предусмотренная в обработчике ветка `404` для доменной ошибки здесь не используется.

### GET /api/v1/hospital/name/{name}

Получить больницу по точному имени.

**URL:** `GET /api/v1/hospital/name/{name}`

**Request:** path-параметр `name` — точное имя, например `Городская больница №1`, с URL-кодированием. Тело отсутствует.

**Response:** `200 OK`, объект больницы в `data`; [полный пример JSON](#hospital-response). Если имя не найдено — `404`:

```json
{
  "message": "no rows in result set"
}
```

### DELETE /api/v1/hospital/{id}

Удалить больницу и её связи с заболеваниями (`ON DELETE CASCADE`).

**URL:** `DELETE /api/v1/hospital/11111111-1111-4111-8111-111111111111`

**Request:** path-параметр `id` — UUID больницы. Тело отсутствует.

**Response:** `200 OK`, тело пустое: обработчик не записывает JSON после успешного удаления.

Невалидный UUID — `400` с `"invalid id"`; отсутствующая запись — `400` с `"no rows in result set"`. Другие ошибки БД также возвращаются как `400` с текстом ошибки. При наличии фиксированного маршрута результата удаление может быть запрещено: `ON DELETE SET NULL` для `hospital_id` конфликтует с `CHECK`, требующим больницу для `routing_type = 'fixed'`.

### PATCH /api/v1/hospital/{id}

Маршрут обновления больницы зарегистрирован, но текущая SQL-реализация содержит ошибку.

**URL:** `PATCH /api/v1/hospital/11111111-1111-4111-8111-111111111111`

**Request:** path-параметр `id` — UUID. DTO содержит те же семь полей, что создание, однако до SQL доходят только `name` и `description`. Отсутствующие строки становятся `""`.

```json
{
  "name": "Городская больница №1 — новое название",
  "description": "Обновлённое описание"
}
```

**Response:** при текущем SQL и схеме миграций ожидается `500 Internal Server Error`:

```json
{
  "message": "internal server error"
}
```

Причина: выполняемый запрос использует `phone` (TEXT) как запасное значение в `COALESCE` для UUID `facility_type_id` и числовых координат. PostgreSQL отклоняет несовместимые типы. Ветка успеха обработчика предусматривает `201 Created` с [объектом больницы](#hospital-response), но текущий запрос её не обеспечивает.

Невалидный UUID — `400` с `"invalid id"`. При ошибочном JSON обработчик пишет `400` с `"invalid json"`, но не останавливается; далее он может дописать второй JSON-ответ в то же тело. Такой ответ целиком не является одним валидным JSON-документом.

## Заболевания

Источники: [DTO](../../internal/sickness/dto.go), [обработчики](../../internal/sickness/handler.go), [репозиторий](../../internal/sickness/repository_sqlc.go), [миграция sickness](../../db/migrations/008_sickness.up.sql), [SQL](../../db/query/sickness.sql).

| Поле request | Тип JSON | Ограничения и фактическое поведение |
| --- | --- | --- |
| `name` | string | В БД `NOT NULL` и `UNIQUE`; непустое значение код не проверяет. |
| `description` | string | В БД допускается `NULL`; при записи отсутствие или JSON `null` превращается в `""`. |

Оба поля DTO — обычные строки без тегов `validate`. При `PATCH` пропущенные поля тоже становятся пустыми строками и перезаписывают значения. В ответах SQL `NULL` для описания становится `""`; для `updated_at` — `"0001-01-01T00:00:00Z"`.

### PATCH /api/v1/sickness/{id}

Обновить название и описание заболевания.

**URL:** `PATCH /api/v1/sickness/22222222-2222-4222-8222-222222222222`

**Request:** path-параметр `id` — UUID; JSON содержит строки `name` и `description`. Передавайте оба значения, чтобы сохранить данные: отсутствие поля очищает соответствующую строку.

```json
{
  "name": "Грипп",
  "description": "Обновлённое описание"
}
```

**Response:** при успехе `201 Created`, обновлённый объект заболевания в `data`; форма совпадает с [примером JSON](#sickness-response).

Особенность: после ошибки декодирования и после ошибки сервиса обработчик продолжает выполнение и дописывает ответ успеха. Ошибочный JSON начинает ответ с `400` и `{"message":"invalid json"}`; неверный UUID, отсутствующая запись или дубликат имени — с `500` и `{"message":"internal server error"}`. Следом записывается ещё один JSON-объект с `data`, поэтому тело ошибки не является одним валидным JSON-документом. При неверном JSON возможна попытка изменения данных.

## Типы учреждений

Источники: [DTO](../../internal/facility_types/dto.go), [обработчики](../../internal/facility_types/handler.go), [репозиторий](../../internal/facility_types/sqlc_repository.go), [миграция facility_types](../../db/migrations/019_facility_types.up.sql), [SQL](../../db/query/facility_types.sql).

| Поле request | Тип JSON | Ограничения и фактическое поведение |
| --- | --- | --- |
| `name` | string | В БД `NOT NULL`, `UNIQUE`. DTO создания помечен `binding:"required"`, но используемый валидатор читает `validate`, поэтому непустое значение не проверяется. |
| `code` | string | В БД `NOT NULL`, `UNIQUE`; ограничений набора значений нет. Тег `binding:"required"` также не выполняет валидацию. |
| `description` | string | В БД допускается `NULL`; отсутствие поля и JSON `null` при записи превращаются в `""`. |

При обновлении передаются обычные строки: отсутствие `name`, `code` или `description` очищает поле. SQL `NULL` для описания при чтении превращается в `""`.

<a id="facility-type-response"></a>

Пример ответа с одним типом учреждения (`ResponseDTO`):

```json
{
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "name": "Больница",
    "code": "hospital",
    "description": "Многопрофильное учреждение",
    "created_at": "2026-09-09T10:00:00Z",
    "updated_at": "2026-09-09T10:00:00Z"
  }
}
```

<a id="facility-type-errors"></a>

**Особенность обработки ошибок:** для всех GET, PATCH и DELETE этой группы обычные ошибки сервиса не попадают ни в одну ветку `switch`. Обработчик завершается без записи статуса и тела, поэтому клиент получает `200 OK` с пустым телом. Это относится к ошибочному UUID, отсутствующей записи, ошибкам БД, ограничениям уникальности при обновлении и внешним ключам при удалении. Такой ответ не подтверждает успех операции. Ошибочный JSON в POST/PATCH обрабатывается отдельно и возвращает `400` с `"invalid json"`.

## Связи больниц и заболеваний

`hospital_id` и `sickness_id` — существующие UUID. Оба столбца в БД `NOT NULL`, внешние ключи удаляются каскадно вместе с родительскими сущностями. У пары `(hospital_id, sickness_id)` нет уникального ограничения: повторный POST создаёт дополнительную связь, а GET может вернуть одинаковую больницу или заболевание несколько раз.

### POST /api/v1/link/hospital/{hospital_id}/sickness/{sickness_id}

Связать больницу с заболеванием.

**URL:** `POST /api/v1/link/hospital/11111111-1111-4111-8111-111111111111/sickness/22222222-2222-4222-8222-222222222222`

**Request:** path-параметры `hospital_id` и `sickness_id` — UUID. Тело отсутствует: поля `CreateDTO` заполняются из URL.

**Response:** `201 Created`:

```json
{
  "data": {
    "id": "44444444-4444-4444-8444-444444444444",
    "sickness_id": "22222222-2222-4222-8222-222222222222",
    "hospital_id": "11111111-1111-4111-8111-111111111111",
    "update_at": "2026-09-09T10:00:00Z",
    "created_at": "2026-09-09T10:00:00Z"
  }
}
```

Поле времени изменения называется именно `update_at`, согласно JSON-тегу DTO. Ошибочный UUID, отсутствующая больница или заболевание возвращают `500` с `"internal server error"`. Повтор пары не является конфликтом и снова возвращает `201`.

### DELETE /api/v1/link/hospital/{hospital_id}/sickness/{sickness_id}

Удалить связи для указанной пары больницы и заболевания. Если созданы дубликаты, SQL удаляет все совпадающие строки.

**URL:** `DELETE /api/v1/link/hospital/11111111-1111-4111-8111-111111111111/sickness/22222222-2222-4222-8222-222222222222`

**Request:** path-параметры `hospital_id` и `sickness_id` — UUID. Тело отсутствует.

**Response:** `200 OK`, тело пустое. Невалидный UUID или отсутствующая связь фактически возвращают `400` с текстом ошибки. Пример отсутствующей связи:

```json
{
  "message": "no rows in result set"
}
```

### GET /api/v1/link/sickness/{id}/hospital

Получить больницы, связанные с заболеванием.

**URL:** `GET /api/v1/link/sickness/22222222-2222-4222-8222-222222222222/hospital`

**Request:** path-параметр `id` — UUID заболевания. Тело отсутствует; параметры списка не предусмотрены.

**Response:** `201 Created` — именно этот статус установлен текущим обработчиком GET:

```json
{
  "data": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "name": "Городская больница №1",
      "description": "Многопрофильная больница",
      "address": "",
      "phone": "",
      "updated_at": "2026-09-09T10:00:00Z",
      "created_at": "2026-09-09T10:00:00Z"
    }
  ]
}
```

Особенность: репозиторий не переносит `address` и `phone`, поэтому здесь они всегда пустые, даже если заполнены у больницы. `facility_type_id`, `latitude` и `longitude` в DTO этого ответа отсутствуют. Если связей нет или заболевание не существует — `201` с `{"data":[]}`. Невалидный UUID и ошибки БД — `500` с `"internal server error"`.

### GET /api/v1/link/hospital/{id}/sickness

Получить заболевания, связанные с больницей.

**URL:** `GET /api/v1/link/hospital/11111111-1111-4111-8111-111111111111/sickness`

**Request:** path-параметр `id` — UUID больницы. Тело отсутствует; параметры списка не предусмотрены.

**Response:** `201 Created`, `data` — массив заболеваний:

```json
{
  "data": [
    {
      "id": "22222222-2222-4222-8222-222222222222",
      "name": "Грипп",
      "description": "Инфекционное заболевание",
      "updated_at": "2026-09-09T10:00:00Z",
      "created_at": "2026-09-09T10:00:00Z"
    }
  ]
}
```

Если связей нет или больница не существует — `201` с `{"data":[]}`. Невалидный UUID и ошибки БД — `500` с `"internal server error"`.
