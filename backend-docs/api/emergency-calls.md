# Вызовы скорой

[К общей документации API](../API_DOCUMENTATION.md)

`emergency_call` — анонимный случай оказания помощи, принадлежащий текущей
смене устройства. Он не содержит персональных данных бригады. Через
`device_access_session` он однозначно связан с устройством и машиной на момент
смены.

Все маршруты требуют токен устройства:

```http
Authorization: Bearer <DEVICE_ACCESS_TOKEN>
```

Токен получается через `POST /api/v1/device-access/login`.

## Жизненный цикл

1. Бригада создаёт вызов.
2. Создаёт `checklist_run`, передав `emergency_call_id`.
3. Заполняет и завершает run. Rule Engine сохраняет результат.
4. Бригада завершает вызов либо отменяет его.

У одной `device_access_session` допускается только один вызов со статусом
`active`. У вызова могут остаться несколько исторических run, но активных run
при закрытии вызова быть не должно.

Координаты являются неизменяемой историей `emergency_call`, а не координатами
учётной записи устройства. Записывать их можно только пока вызов активен.
`captured_at` приходит из GPS-приёмника, а `received_at` проставляется сервером;
это позволяет отличить реальную позицию в момент измерения от отложенной
доставки при плохой связи.

Статусы:

- `active` — случай открыт;
- `completed` — есть хотя бы один завершённый run, вызов закрыт;
- `cancelled` — случай отменён, `completed_at` заполнен.

## Объект emergency call

```json
{
  "data": {
    "id": "1022cf0d-2334-4a18-af99-126e8a4141ca",
    "device_access_session_id": "f7c8a0ad-38d7-466c-a161-adcab452ef2e",
    "status": "active",
    "started_at": "2026-09-18T12:00:00Z",
    "completed_at": null,
    "created_at": "2026-09-18T12:00:00Z",
    "updated_at": "2026-09-18T12:00:00Z"
  }
}
```

## POST /api/v1/emergency-calls/

Открывает новый вызов для текущей device-сессии. Тело отсутствует.

Ответ: `201 Created`, объект вызова в `data`.

Ошибки: `401` — токен или сессия неактивны; `409` — у этой сессии уже есть
активный вызов.

## GET /api/v1/emergency-calls/active

Возвращает текущий активный вызов сессии. Полезен после перезапуска приложения,
чтобы продолжить незавершённый сценарий.

Ответ: `200 OK`, объект вызова в `data`.

Ошибки: `401` — токен или сессия неактивны; `404` — активного вызова нет.

## GET /api/v1/emergency-calls/{id}

Возвращает вызов только текущей device-сессии, включая закрытый.

Ответ: `200 OK`, объект вызова в `data`.

Ошибки: `400` — `id` не UUID; `401` — токен или сессия неактивны; `404` —
вызов отсутствует либо принадлежит другой сессии.

## POST /api/v1/emergency-calls/{id}/locations

Добавляет одну GPS-координату в историю активного вызова. Устройство отправляет
координату сразу после получения от GPS и перед завершением чеклиста. Повторный
запрос не обновляет старую запись, а создаёт новую историческую точку.

```json
{
  "latitude": 55.755826,
  "longitude": 37.6173,
  "accuracy_meters": 8.5,
  "captured_at": "2026-09-18T12:04:55Z"
}
```

Все поля обязательны. Координаты используются в формате WGS 84: `latitude` от
`-90` до `90`, `longitude` от `-180` до `180`. `accuracy_meters` — точность,
которую вернуло устройство, от `0` до `100000`. Время `captured_at` передаётся
в RFC 3339 и не может быть более чем на пять минут впереди времени сервера.

Ответ: `201 Created`.

```json
{
  "data": {
    "id": "90d7ca80-6cfe-4e4e-a818-63645e0d2a51",
    "emergency_call_id": "1022cf0d-2334-4a18-af99-126e8a4141ca",
    "latitude": 55.755826,
    "longitude": 37.6173,
    "accuracy_meters": 8.5,
    "captured_at": "2026-09-18T12:04:55Z",
    "received_at": "2026-09-18T12:04:56Z"
  }
}
```

Ошибки: `400` — неверное тело, координаты, точность или время; `401` — токен
или device-сессия неактивны; `409` — вызов закрыт либо не принадлежит текущей
сессии.

## GET /api/v1/emergency-calls/{id}/location

Возвращает последнюю точку вызова по времени `captured_at`. Закрытый вызов можно
читать до завершения device-сессии, но добавлять точки после его закрытия нельзя.

Ответ: `200 OK`, объект координаты того же формата, что у `POST`.

Ошибки: `400` — `id` не UUID; `401` — токен или сессия неактивны; `404` — у
вызова нет сохранённой координаты либо вызов принадлежит другой сессии.

## POST /api/v1/emergency-calls/{id}/complete

Закрывает активный вызов статусом `completed`. Тело отсутствует.

Перед закрытием сервер проверяет, что у вызова нет `in_progress` run и есть
хотя бы один `completed` run. Это не позволяет потерять случай с незавершённой
анкетой и не позволяет пометить как успешно завершённый вызов без результата
чеклиста.

Ответ: `200 OK`, объект вызова в `data`.

Ошибки: `400` — `id` не UUID; `401` — токен или сессия неактивны; `404` —
вызов отсутствует либо чужой; `409` — вызов уже закрыт, есть активный run или
нет ни одного завершённого run.

## POST /api/v1/emergency-calls/{id}/cancel

Закрывает активный вызов статусом `cancelled`. Тело отсутствует. Отмена
возможна, только когда у вызова нет `in_progress` run; завершённый run для
отмены не требуется.

Ответ: `200 OK`, объект вызова в `data`.

Ошибки: `400` — `id` не UUID; `401` — токен или сессия неактивны; `404` —
вызов отсутствует либо чужой; `409` — вызов уже закрыт или есть активный run.

## POST /api/v1/emergency-calls/{id}/destination/resolve

Создаёт основное назначение больницы по последнему завершённому checklist run
вызова. Операция идемпотентна: повторный запрос возвращает уже сохранённое
назначение и не пересчитывает кандидатов.

Для `fixed` и `by_service_area` ответ сразу имеет `status: "selected"`.
Для `by_tag` он имеет `status: "awaiting_selection"` и массив `candidates`.
Если подходящей больницы нет — `status: "no_candidates"`.

Для `by_service_area` нужна GPS-точка не старше двух минут. Ответ: `201 Created`.
Ошибки: `401` — сессия устройства неактивна; `409` — вызов неактивен, нет
завершённого результата, нет routing-конфигурации или GPS-точка отсутствует/
устарела.

## GET /api/v1/emergency-calls/{id}/destination

Возвращает сохранённое назначение и неизменяемый список кандидатов. Доступно
своей device-сессии и после закрытия вызова. Ответ: `200 OK`.

## POST /api/v1/emergency-calls/{id}/destination/select

Выбирает одну больницу только из сохранённых кандидатов `by_tag`.

```json
{ "hospital_id": "fe0fdcff-1440-4c5e-9e65-69726498e6e9" }
```

Ответ: `200 OK`, статус меняется на `selected`. Выбор нельзя заменить повторным
запросом; это сохраняет фактическое решение бригады для аналитики.

Подробная настройка зон и режимов: [hospital-routing.md](hospital-routing.md).
